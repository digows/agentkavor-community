# Kavor 1.5.0

## Основные изменения

- Kavor для Windows опубликован в Microsoft Store вместе с прямой загрузкой NSIS. Microsoft подписывает и
  распространяет пакет Store и управляет обновлениями установок из этого канала.
- Сборки для обеих архитектур macOS подписываются Apple Developer ID и проходят нотариальную проверку Apple.
  Gatekeeper теперь может проверить издателя Kavor и билет нотариализации вместо первоначального предупреждения о
  неизвестном разработчике.
- Для каждого CodingAgent добавлен выбор рабочего каталога. Сессию можно запустить из любого существующего каталога,
  выбранного пользователем, включая каталог за пределами Workspace, сохранив независимую привязку Git и worktree.
- Подключённые CodingAgents могут пассивно читать завершённые ходы текущей provider-сессии доступного peer. История
  разбита на страницы с курсором; чтение не отправляет ввод provider, не активирует peer и не создаёт сообщение Kavor.
- Улучшена доставка контекста Kavor Skill: инструкции по созданию Specification доступны до её подключения, а
  Trigger получает релевантный рабочий контекст напрямую.

## Исправления

- Длинные сообщения сессий CodingAgent полностью сохраняются между ограниченными страницами истории без обрезания
  оставшегося текста.
- Изменение provider-сессии во время пассивного чтения peer обнаруживается, а устаревшее продолжение отклоняется
  вместо объединения фрагментов разных сессий.
- Сессии Codex проверяются перед возобновлением; текущая сессия, архивированная извне, заменяется без потери
  восстанавливаемой истории provider.
- Завершённая история Antigravity читается между страницами provider; пассивная история унифицирована для Claude
  Code, Codex, Antigravity, OpenCode и Grok.
- Длинные аргументы запуска и пути выбранных рабочих каталогов остаются в границах панели настроек CodingAgent.

## Установка

Загрузите Kavor с <https://download.agentkavor.com>. Страница определяет текущую платформу и позволяет показать все
доступные пакеты. Существующие прямые установки могут проверить обновление в настройках Software Update. Ручная
миграция данных Workspace не требуется: перед обновлением schema Kavor создаёт резервные копии поддерживаемых
локальных баз данных.

- Windows x64 доступен в Microsoft Store или как пользовательский установщик NSIS. Microsoft подписывает и
  обновляет установки Store. Прямой установщик остаётся неподписанным, поэтому Microsoft SmartScreen может запросить
  явное подтверждение.
- Для macOS 13+ доступны отдельные DMG для Apple Silicon и Intel, подписанные Apple Developer ID Kavor и
  нотариализованные Apple. Этот выпуск переводит прежнюю ad-hoc подпись на стабильную Developer ID. Если macOS
  отклонит автоматический переход со старой сборки, установите соответствующий DMG вручную с постоянной страницы
  загрузки; существующие данные Kavor сохранятся.
- Для Linux x64 доступны AppImage и DEB. AppImage поддерживает обновления через Kavor с явным согласованным
  перезапуском; DEB обновляется вручную со страницы загрузки.

## Известные ограничения

- Schedule Trigger требует запущенный runtime Kavor, активную машину, вошедшего пользователя и активную целевую
  сессию. Пропущенный запуск записывается и предлагается как явный ручной запуск; при следующем старте он никогда не
  выполняется автоматически.
- Пакеты Windows ARM64 и Linux ARM64 не предоставляются, пока нативные проверки PTY, SQLite, ограничения процессов и
  упакованного runtime нельзя выполнять в соответствующих CI-средах.
- Прямые загрузки Windows пока не имеют сертификата издателя Authenticode; пакеты Microsoft Store подписывает
  Microsoft.
- Первый переход с ad-hoc сборки macOS на сборку с Developer ID может потребовать ручной установки DMG или одного
  разрешения Keychain для `Kavor Safe Storage`. Последующие подписанные выпуски сохраняют тот же Apple Team ID.
- Microsoft Store может опубликовать эту версию после независимой сертификации; прямые stable-пакеты сразу доступны
  на странице загрузки Kavor.
