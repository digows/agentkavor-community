# Kavor 1.4.0

## Основные изменения

- Добавлен Grok в качестве provider для CodingAgent: используется клиент ACP с настройкой, интерактивным вводом и
  поддержкой именования и каталога сессий через wire-соглашение расширяемых методов ACP.
- Добавлен OpenCode в качестве provider для CodingAgent: жизненный цикл аутентифицированного локального сервера,
  поддержка создания, возобновления, форка, списка и именования сессий, включая установку версии для Windows без
  отката к WSL.
- В палитру Canvas добавлен инструмент выбора provider, поэтому размещение node CodingAgent теперь включает явный
  выбор provider, с общим помощником жеста (нажатие против перетаскивания), используемым во всей палитре.
- Во встроенных представлениях PTY для Terminal и CodingAgent теперь отображаются встроенные изображения Sixel и
  iTerm2, соответствующие тому, что уже может выводить базовый процесс.
- Добавлена поддержка нескольких корней specification на Workspace, с соответствующими изменениями в настройках
  Specification, панели Backlog и дереве папок, чтобы Specification можно было организовать в более чем одном
  корне.

## Исправления

- Исправлено состояние гонки при передаче Onboarding, при котором лениво загружаемый маршрут Workspace мог
  приостановиться и сбросить флаг готовности Onboarding, оставляя Canvas гидратированным позади этапа, который
  Onboarding так и не освобождал.
- Откатывается session id provider, который adapter придумал, но так и не подтвердил, если Interactive PTY
  завершается до готовности к запуску, поэтому сбой при первом запуске больше не может оставить Node навсегда
  указывающим на сессию, которую provider никогда не создавал.
- Область защиты окружения запуска provider сужена до двух переменных, которыми Kavor действительно владеет,
  вместо всего унаследованного окружения, и добавлен явный результат запуска provider «требуется обновление»
  наряду с уже существующим «команда не найдена», отображаемый в оверлее установки, панели инструментов и
  обрамлении node.
- Перетаскивание нескольких node на Canvas теперь сохраняется как одно сгруппированное перемещение вместо
  отдельных записей для каждого node.
- Стабилизированы отложенное отображение PTY, разрешение окружения login shell и трекер экрана терминала xterm.
- Исправлена проблема, из-за которой node CodingAgent для OpenCode навсегда зависали в состоянии «Working», когда
  транспорт событий provider терял переход в состояние простоя сессии; теперь Kavor в этом случае напрямую
  сверяет реальный статус сессии.

## Установка

Скачайте Kavor на <https://download.agentkavor.com>. Страница определяет текущую платформу, а также показывает все
доступные пакеты. Существующие прямые установки могут проверить наличие этой версии в настройках обновления ПО
Kavor. Ручная миграция данных Workspace не требуется; Kavor создаёт резервную копию поддерживаемых локальных баз
данных перед применением обновлений схемы.

- Windows x64 использует ассистированный установщик NSIS для одного пользователя. Установщик пока не подписан,
  поэтому Microsoft SmartScreen может потребовать явного подтверждения.
- macOS 13+ предоставляет отдельные DMG для arm64 и x64. Сборки подписаны ad-hoc, но не нотариально заверены;
  следуйте инструкциям по Gatekeeper на странице загрузки. Обновления, управляемые Kavor, используют ZIP
  соответствующей архитектуры и предлагают явный согласованный перезапуск после повторной проверки кэшированного
  артефакта. Ручная загрузка остаётся доступной в любое время.
- Linux x64 предоставляет пакеты AppImage и DEB. AppImage поддерживает обновления, управляемые Kavor, с явным
  согласованным перезапуском; обновления DEB устанавливаются вручную со страницы загрузки.

## Известные ограничения

- Schedule Trigger требуют, чтобы среда выполнения Kavor была запущена, машина не спала, пользователь выполнил
  вход, а целевая сессия была активна. Пропущенное событие, произошедшее пока Kavor не был запущен, записывается и
  предлагается как явный ручной запуск; оно никогда не выполняется автоматически при следующем запуске.
- Пакеты для Windows ARM64 и Linux ARM64 не включены, пока их нативные gate для PTY, SQLite, изоляции процессов и
  упакованной среды выполнения не смогут работать в соответствующих средах CI.
- Прямые загрузки для Windows пока не имеют сертификата publisher Authenticode.
- Пакеты для macOS пока не имеют подписи Developer ID или нотариального заверения. Gatekeeper может потребовать
  ручного подтверждения, а замена ad-hoc сборки может привести к тому, что macOS снова запросит доступ к
  `Kavor Safe Storage` в Keychain.
- Распространение через Microsoft Store не входит в этот релиз.
