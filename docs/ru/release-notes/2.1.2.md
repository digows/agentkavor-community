# Kavor 2.1.2

## Основные изменения

- Hotfix для аккаунтов CodingAgents, вложений Channels и работы с Browser.

## Исправления

- Предотвращает принудительное обновление токенов OAuth при обычном чтении данных аккаунтов Codex и повторные
  запросы в рамках одного решения о выборе. Сохраняет поведение выбора Automatic и Auto Rotate.
- Новые управляемые аккаунты Codex, Claude Code и Grok больше не клонируют личные настройки. Аутентификация
  каждого аккаунта остаётся изолированной; нативная история сохраняется в каноническом расположении provider,
  а интеграция Kavor подготавливается отдельно.
- Исправляет подготовку и очистку вложений Channels: при ошибке подготовки сохраняет исходные файлы и вложения,
  уже привязанные к сообщению, удаляет временные файлы отправки и повторяет очистку просроченных копий после
  временных сбоев.
- В Browser безымянные открытия новых страниц, например ссылки `target="_blank"`, теперь используют вкладки
  того же Node. Явные всплывающие окна, именованные цели и POST-запросы по-прежнему открываются в нативных окнах.
- Исправляет операции управления фоновыми страницами, отслеживание геометрии взаимодействия и освобождение
  наблюдателей. Убирает постоянный опрос геометрии и ограничивает предпросмотры сетевых ответов, сохраняемые Browser.

## Установка

Скачайте Kavor с <https://download.agentkavor.com> или проверьте обновления в настройках Software Update.

- **Windows x64:** Microsoft Store или NSIS-установщик с участием пользователя. Microsoft подписывает и обновляет
  установки Store. Прямой установщик остаётся неподписанным и может вызвать предупреждение SmartScreen.
- **macOS 13+:** отдельные подписанные и нотарифицированные DMG для Apple Silicon и Intel. Автообновления
  используют ZIP соответствующей архитектуры; DMG остаётся доступным для ручной установки.
- **Linux x64:** AppImage и DEB. AppImage поддерживает управляемые Kavor обновления с явным согласованным
  перезапуском; обновления DEB устанавливаются вручную.

## Известные ограничения

- Данные об использовании и восстановление аутентификации по-прежнему зависят от provider. Интервалы обновления
  данных об использовании аккаунтов, допустимость аккаунтов, пороги ротации и лимиты providers не меняются.
- Существующие управляемые профили не переносятся и не очищаются автоматически; ранее скопированные настройки
  сохраняются.
- Новые вкладки для безымянных открытий не сохраняют нативную связь через `WindowProxy` и `window.opener`.
  Сайты, которым она нужна, включая некоторые сценарии входа или оплаты, могут не завершить такой сценарий
  при этом способе открытия.
- Пакеты Windows ARM64 и Linux ARM64 не включены. Доступность в Microsoft Store может наступить после прямой
  публикации из-за независимой сертификации Microsoft.
