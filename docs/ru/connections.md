# Матрица поддерживаемых Connections в Kavor

Connection — не стрелка рабочего процесса. Это явное ненаправленное отношение, которое помещает два Nodes в один
достижимый компонент Canvas.

Для CodingAgent важен весь граф: он может работать с любым Node, достижимым по пути допустимых Connections, даже без
прямого соединения с ресурсом. Прямая Connection по-прежнему важна для выбора цели Schedule, передачи параметров или
задания Guardrail между конкретным CodingAgent и ресурсом.

Эта страница — публичный справочник по допустимым прямым парам и особым контрактам каждой из них.

## Как читать Connection

У Connection есть три разных обязанности:

1. **Существование:** она соединяет Nodes в один достижимый компонент графа.
2. **Параметры:** она хранит обязательную настройку, если она нужна этой паре.
3. **Guardrails:** она отнимает возможности у поведения, которое обычно разрешено между двумя Nodes.

Connections — двусторонние отношения. Kavor хранит два endpoints в каноническом порядке, но этот порядок не означает
поток, управление или приоритет. У сообщения по-прежнему есть отправитель и получатель, а у Trigger — цель. Эти
направления относятся к выполняемой операции, а не к сохранённой Connection.

Матрица перечисляет прямые пары. Nodes без допустимой прямой пары могут входить в один доступный компонент через другие поддерживаемые Connections; визуальная близость не даёт доступа.

## Поддерживаемые сочетания

| Пара Nodes | Что позволяет Connection | Параметры | Доступный Guardrail | Основной пример |
| --- | --- | --- | --- | --- |
| **CodingAgent + Specification** | Читать метаданные и канонический Markdown, работать с lifecycle и регистрировать долговечные outputs, когда это разрешено. | Нет | `specification_read_only` | Spec Writer, Builder и Reviewer используют общий контракт. |
| **CodingAgent + Sticky Note** | Читать и писать неформальную память в Markdown с контролем версий; при каждой записи выбирается append или replace. | Нет | `sticky_note_read_only` | Открытые решения, прогресс, наблюдения и видимые handoffs. |
| **CodingAgent + Terminal** | Читать output, выполнять команды, отслеживать или прерывать связанный запуск и взаимодействовать с foreground-процессом, когда это разрешено. | Нет | `terminal_read_only` | Диагностика, тесты, логи или помощь в контролируемой SSH-сессии. |
| **CodingAgent + File** | Сделать канонический источник в filesystem явным в графе для чтения, проверки или изменения, когда это разрешено. | Нет | `file_read_only` | Ограничить область модулем, PDF, изображением, отчётом или конфигурацией. |
| **CodingAgent + Diagram** | Сделать исходный файл и результат рендеринга диаграммы достижимыми в графе. | Нет | `diagram_read_only` | Создать визуальное предложение и проверить ошибки текущего исходного файла. |
| **CodingAgent + WebBrowser** | Предоставить агенту контролируемый доступ к живым страницам этого WebBrowser. | Нет | Нет | Человек и агент переходят, заполняют, проверяют и фиксируют доказательства в одном видимом состоянии. |
| **CodingAgent + CodingAgent** | Сформировать достижимый граф для асинхронных сообщений, ответов, независимой проверки и параллельной работы. | Режим доставки по умолчанию | Блокировать After turn, Native input или Send now | Builder запрашивает проверку у Reviewer. |
| **Specification + Terminal** | Экспортировать канонический абсолютный путь Specification в сессию Terminal. | Обязательное имя переменной окружения | Нет | Проверить, изучить или сравнить Markdown в Specification. |
| **File + Terminal** | Экспортировать канонический абсолютный путь File в сессию Terminal. | Обязательное имя переменной окружения | Нет | Запустить script или использовать SQL-файл, не копируя его путь между окнами. |
| **Diagram + Terminal** | Экспортировать канонический абсолютный путь исходного файла Diagram в сессию. | Обязательное имя переменной окружения | Нет | Использовать исходный файл диаграммы как вход инструмента проекта. |
| **Trigger + CodingAgent** | Доставить в заданное время prompt в CodingAgent с активной сессией. | Нет | Нет | Разбудить Maintainer для анализа сбоев, подготовки отчёта и запроса проверки. |
| **Trigger + Terminal** | Доставить в заданное время команду в активную сессию Terminal. | Нет | Нет | Запустить тесты, проверку базы данных или script обслуживания. |

Connections между CodingAgent и ресурсом — не единственный способ достичь ресурса. Это самый явный способ включить
его в граф агента и единственное место для Guardrail, ограничивающего именно эту пару.

У CodingAgent + WebBrowser есть собственный контракт: Connection делает реальные страницы этого Node доступными
для контролируемой навигации, взаимодействия, ожидания и фиксации. Она не наследует общий Guardrail и не обходит
аутентификацию, разрешения сайта или решения человека. Выделенный профиль браузера принимает недействительные
сертификаты разработки; это явное поведение браузера, а не разрешение, созданное Connection.

## Guardrails ограничивают, а не предоставляют доступ

По умолчанию граф открыт для достижимых Nodes. Guardrail хранит выбранное пользователем ограничение на прямой
Connection между CodingAgent и ресурсом:

| Guardrail | Connection | Эффект |
| --- | --- | --- |
| `specification_read_only` | CodingAgent + Specification | Сохраняет чтение и запрещает через Kavor изменения lifecycle и outputs. Прямое редактирование Markdown становится явным контрактом «только для чтения». |
| `sticky_note_read_only` | CodingAgent + Sticky Note | Сохраняет чтение и блокирует append или replace содержимого. |
| `terminal_read_only` | CodingAgent + Terminal | Сохраняет просмотр Terminal и блокирует операции, которые изменили бы сессию, процесс или его ввод. |
| `file_read_only` | CodingAgent + File | Объявляет, что agent не должен изменять канонический источник. |
| `diagram_read_only` | CodingAgent + Diagram | Сохраняет чтение и проверку результата; запрещает запись в исходный файл, переименование или удаление Node. |
| `coding_agent_message_after_turn_blocked` | CodingAgent + CodingAgent | Блокирует доставку After turn между парой. |
| `coding_agent_message_native_blocked` | CodingAgent + CodingAgent | Блокирует доставку Native input между парой. |
| `coding_agent_message_immediate_blocked` | CodingAgent + CodingAgent | Блокирует Send now и steering между парой. |

Guardrails принадлежат прямой Connection между CodingAgent и ресурсом. Альтернативный маршрут в графе не снимает
ограничение, существующее для этой прямой пары.
Ограничение на Connection другого агента при этом не становится глобальной политикой Node.

Если Guardrail блокирует операцию через Kavor, она отклоняется до появления побочных эффектов. Files, Diagrams и содержимое
Specifications также могут быть доступны через собственные filesystem-инструменты harness. В таких случаях
Guardrail — видимый и контролируемый контракт, а не sandbox операционной системы.

Guardrail не создаёт Connection, не делает Node достижимым и не повышает разрешения. Если ресурс не должен участвовать
в графе, не создавайте Connection.

## Доставка между CodingAgents

Прямая Connection задаёт режим для сообщений без явного выбора. По умолчанию используется **Native input**. Агент может запросить другой режим для сообщения, если разрешают Guardrails.

- **After turn:** ждёт завершения хода и доступности адресата.
- **Native input:** использует обычную обработку ввода provider, который может принять, поставить в очередь, скорректировать направление или прервать согласно своим возможностям и настройкам. Доставка без прерывания не гарантируется.
- **Send now:** запрашивает немедленный ввод с возможным прерыванием. Требует поддержки provider и не отменяет уже сделанные изменения, команды или эффекты.

![Настройки Connection между CodingAgents: After turn, Native input, Send now и Guardrails доставки](https://media.agentkavor.com/releases/2.0.0/agent-communication/delivery/master.cda7ab810311.png)

Guardrail прямой Connection действует и при наличии другого пути в графе. Ни один режим не обходит черновики, подтверждения и удержанную доставку человека. Принятие и доставка не означают завершение работы.

## Connections с переменными окружения

Три пары передают пути через переменные окружения:

- **File + Terminal**;
- **Diagram + Terminal**;
- **Specification + Terminal**.

Во всех трёх случаях вы выбираете имя переменной окружения. Значение, предоставленное Terminal, — канонический абсолютный
путь к источнику, а не содержимое файла.

Например, File, подключённый как `CHECK_SQL`, можно использовать в shell так:

```sh
sqlite3 app.db < "$CHECK_SQL"
```

Kavor применяет значение при запуске сессии Terminal. Если Connection или её параметр изменятся, пока shell открыт,
интерфейс покажет, что для применения переменной требуется перезапуск сессии. `TERM` и `COLORTERM` — зарезервированные
имена, которые нельзя использовать для этих параметров.

## Особое ограничение Schedule

Schedule — доступный в продукте источник Trigger. У Trigger может быть не более одной прямой цели: CodingAgent или
Terminal. Connection выбирает эту цель; её id не дублируется в настройках. Trigger не соединяется напрямую со
Specification, File или Sticky Note и не распределяет одно срабатывание между несколькими целями.

Остальная часть графа может расширить возможности цели, не расширяя её разрешения. Разбуженный Trigger CodingAgent
может работать с уже достижимыми Nodes при тех же Guardrails и ограничениях сессии.

Для доставки Kavor должен быть запущен, машина не должна спать, а сессия цели должна быть открыта. При запуске Kavor
восстанавливает отмеченные для сохранения сессии, если они являются целями работающих Triggers, включая другие
Workspaces пользователя. Trigger не запускает намеренно закрытую сессию и не превращает внешние эффекты в
exactly-once операции. Каждый TriggerFiring хранит долговечный результат для последующей проверки.
Удаление Connection с целью ставит Trigger на паузу и сохраняет причину.

О повторении, `Run now` и долговечной истории см. [Schedule: добавьте часы к графу](./schedule.md).

## Несуществующие сочетания

Kavor отклоняет любую пару, которой нет в матрице. В частности:

- Trigger + Specification;
- Trigger + File;
- Trigger + Sticky Note;
- Specification + File;
- Specification + Sticky Note;
- File + Sticky Note;
- File + File;
- Sticky Note + Terminal;
- Sticky Note + Sticky Note;
- WebBrowser + Specification;
- WebBrowser + Sticky Note;
- WebBrowser + Terminal;
- WebBrowser + File;
- WebBrowser + Trigger;
- WebBrowser + WebBrowser;
- Terminal + Terminal.

Node также нельзя соединить с самим собой. Перестановка двух одинаковых endpoints не создаёт другую Connection,
поскольку у отношения нет сохранённого направления.

Эти ограничения не мешают полезным сочетаниям. Например, Specification и Sticky Note могут участвовать в одном графе,
если соединены с CodingAgents поддерживаемыми парами. Между ними нет лишь прямой Connection.

Близость на Canvas, упоминание в сообщении или участие в одном Workspace не заменяют путь Connections.

## Выбирайте минимальную Connection, которая решает задачу

Прежде чем соединить два Nodes, спросите, какой конкретной возможности не хватает:

- agent нужен долговечный замысел? Подключите Specification;
- человеку и agent нужна общая рабочая память? Подключите Sticky Note;
- agent должен выполнить или наблюдать процесс? Подключите Terminal;
- нужно явно обозначить канонический источник? Подключите File;
- нужно визуальное объяснение с редактируемым исходным текстом? Добавьте [Diagram](./diagrams.md);
- человеку и агенту нужна живая страница? Подключите WebBrowser;
- другая точка зрения улучшит реализацию или проверку? Подключите ещё один CodingAgent;
- время действительно должно запускать активность? Добавьте Trigger в последнюю очередь.

Не соединяйте каждого CodingAgent с каждым ресурсом автоматически. Выбирайте минимальную топологию, сохраняющую
достижимость, и добавляйте прямую Connection, когда она делает Canvas понятнее, передаёт параметр или нужна для
отдельного Guardrail.

## Скопируйте prompt для проверки Connections

Используйте в CodingAgent проверяемого компонента и укажите задачу. Это не разрешает подключаться к существующим Nodes вне графа или менять Guardrails.

```prompt
Изучи официальную документацию Connections и мой достижимый компонент.
Объясни, какие ресурсы уже доступны через топологию и какие пары имеют прямые параметры или Guardrails.
Для описанной задачи указывай лишние или недостающие Connections только при конкретном обосновании.
Не меняй Canvas. Покажи предложение и последствия каждого изменения до моего решения.
```

**Ожидаемый результат:** Ревью различает транзитивную достижимость и прямые контракты. Совет не открывает доступ, не снимает Guardrail и не превращает Connections в стрелки исполнения.
