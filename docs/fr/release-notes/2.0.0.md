# Kavor 2.0.0

> Révision éditoriale du 16 octobre 2026 : clarifie la présentation d'Agent Kavor et de Browser sans modifier
> les binaires de la 2.0.0. Les [notes originales](https://github.com/digows/agentkavor-community/blob/285143eb2012de9e702c2cd80bb5d5f1a75ea8fc/docs/fr/release-notes/2.0.0.md)
> restent disponibles ; cette révision ne modifie pas la copie intégrée à l'application.

## Nouveautés

- **Agent Kavor via WhatsApp, le premier Channel public.** Échangez avec vos agents locaux dans une conversation
  personnelle ou un groupe dédié à chaque Workspace. Choisissez le contexte et le CodingAgent, suivez la progression,
  répondez aux questions et échangez des pièces jointes. Associez votre compte dans la configuration de Channels de
  la barre supérieure ; Workspace Channels apparaît après l'association et les paramètres s'enregistrent automatiquement.
  L'expérience améliore l'association, la reconnexion et les retours de commandes, états, annulations et erreurs,
  tout en préservant le contenu d'origine et la corrélation de Motion Photo lors des réexécutions natives.
- **Collaboration entre CodingAgents.** Envoi natif via le provider, livraison après le tour et interruption explicite
  lorsqu'elle est autorisée, dans le respect des Guardrails des Connections et des brouillons humains. Les agents
  connectés peuvent aussi consulter les tours terminés de leurs pairs dans un historique borné et paginé.
- **Browser reste actif, même hors du Canvas visible.** Les agents connectés peuvent contrôler les onglets WebBrowser
  en arrière-plan. Start, Shutdown et la mise en sourdine restent sous contrôle explicite, en préservant les choix
  d'arrêt, les onglets enregistrés et les données partagées des sites lors des changements de cycle de vie de l'UI.
- **Ressources à la demande.** Les processus auxiliaires démarrent au besoin et les ressources inactives sont libérées
  sans perdre l'état persisté de Workspace, Terminal, CodingAgent et Browser. Le nettoyage des PTY et des processus
  auxiliaires a également été amélioré.
- **Typographie et identité visuelle renouvelées.** Inter et Geist Mono sur le desktop, visuels de l'application
  affinés et transparence des icônes rétablie sur macOS.

## Corrections

- Préserve les options natives de démarrage de CodingAgent, notamment les arguments explicites de modèle,
  permissions, session et répertoire de travail, sans remplacer silencieusement les choix de l'utilisateur.
- Corrige la fin des tours de Grok et les cas qualifiés de lecture passive des sessions, et améliore la corrélation
  de la livraison native des messages et l'acquittement des notifications entre fenêtres de Workspace.
- Affiche les questions natives de CodingAgent et inclut le Workspace d'origine dans les titres des notifications
  du système pour mieux identifier les activités parallèles de plusieurs Workspaces.

## Installation

Téléchargez Kavor depuis <https://download.agentkavor.com>. Les installations directes existantes peuvent rechercher
cette version dans les paramètres Software Update. Les mises à niveau de la base de données du Workspace suivent
le parcours de migration de Kavor avec sauvegarde.

- Windows x64 est disponible dans Microsoft Store ou via l'installateur NSIS assisté par utilisateur. Microsoft signe
  et met à jour les installations Store. L'installateur direct reste non signé ; Microsoft SmartScreen peut donc
  demander une confirmation explicite.
- macOS 13+ propose des DMG distincts pour Apple Silicon et Intel, signés avec l'Apple Developer ID de Kavor et
  notarisés par Apple. Les mises à jour automatiques utilisent le ZIP correspondant à l'architecture et conservent
  le DMG comme solution manuelle.
- Linux x64 propose AppImage et DEB. AppImage prend en charge les mises à jour gérées par Kavor avec un redémarrage
  coordonné explicite ; les mises à jour DEB s'installent manuellement depuis la page de téléchargement.

## Limitations connues

- Un hyperlien OSC 8 de Terminal imprimé sur une ligne déjà sous le pointeur peut nécessiter de déplacer le pointeur
  vers une autre ligne puis de revenir avant de l'ouvrir. Cette limite du cache de survol de xterm reste présente.
- L'audit des dépendances de production signale des avis upstream de déni de service non résolus pour
  [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) et
  [sprintf-js](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). Ces versions étaient déjà présentes dans Kavor 1.7.1.
  La surveillance récursive du Workspace désactive l'expansion glob sur le chemin utilisant braces ; il s'agit
  d'une atténuation, pas d'une dépendance corrigée.
- WhatsApp nécessite un compte associé, un accès réseau et Kavor en cours d'exécution sur le desktop avec une session authentifiée. L'intégration
  par appareil associé n'est pas la WhatsApp Business API hébergée par Meta ; les restrictions du compte WhatsApp
  restent sous le contrôle de Meta.
- Le Browser Profile dédié et partagé de Kavor accepte tous les certificats serveur pour permettre le développement
  local. Un réseau hostile peut donc usurper les sites ouverts dans ce profil, y compris ceux auxquels l'utilisateur
  se connecte. La session de l'application Kavor conserve la vérification normale des certificats de Chromium.
- Les Nodes WebBrowser ne réutilisent pas le profil, les extensions, l'historique ni les cookies du Chrome externe
  de l'utilisateur. Supprimer un Node n'efface pas les données partagées des sites ; les paramètres globaux de Kavor
  permettent de vider explicitement le cache, les cookies et les données des sites.
- Les frames intersites isolées dans un autre processus Chromium sont signalées comme omises et ne peuvent pas être
  contrôlées à travers la frontière de sécurité du guest.
- Les packages Windows ARM64 et Linux ARM64 ne sont pas inclus. Les téléchargements directs Windows n'ont pas encore
  de certificat d'éditeur Authenticode ; Microsoft signe les packages Microsoft Store. La disponibilité dans Store
  peut suivre la release stable directe après la certification indépendante de Microsoft.
