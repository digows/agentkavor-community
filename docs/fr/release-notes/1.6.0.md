# Kavor 1.6.0

## Nouveautés

- Ajoute le Node WebBrowser au Canvas comme navigateur Chromium complet utilisé par une personne. Il prend en charge
  les onglets persistants, la navigation, l'historique, les fenêtres contextuelles, les téléchargements, les demandes
  d'autorisation, la recherche, le zoom, DevTools et un Profil de Navigateur Kavor dédié et partagé par les Nodes
  WebBrowser de l'Utilisateur.
- Permet à un CodingAgent connecté de contrôler exactement la page active visible par l'Utilisateur grâce à des
  opérations Kavor bornées pour l'état de page, la navigation, les snapshots d'accessibilité, les actions,
  l'évaluation JavaScript, les attentes, les captures d'écran, l'inspection de la console et du réseau, les corps de
  réponse et les règles réseau limitées à la page.
- Permet aux CodingAgents de créer des Nodes WebBrowser par des modifications atomiques du Canvas, avec une URL
  initiale facultative, puis de découvrir et d'utiliser le Node avec le même modèle de Connection et d'accessibilité
  que dans le reste de Kavor.
- Réduit le contexte automatique du CodingAgent tout en conservant l'accès à la demande au graphe complet, au layout,
  aux métadonnées et résultats de Specification et aux Skills nécessaires à la tâche en cours.

## Corrections

- Démarre et bifurque les sessions Codex sans attendre un fichier de rollout que Codex n'a pas encore créé, puis
  enregistre la session du fournisseur lorsque le premier prompt envoyé établit son identité native.
- Préserve la reprise Codex, la filiation des bifurcations et les noms de session synchronisés lorsque la session du
  fournisseur se matérialise après l'ouverture du terminal interactif.
- Utilise un vocabulaire WebBrowser cohérent dans le domaine, le Canvas, IPC, le catalogue MCP, les Skills, la
  partition de profil et le schéma interne du navigateur.
- Publie des contrats d'entrée complets pour les actions et attentes WebBrowser afin que les CodingAgents reçoivent
  tous les champs pris en charge au lieu d'un schéma d'outil supérieur vide.

## Installation

Téléchargez Kavor depuis <https://download.agentkavor.com>. La page détecte la plateforme actuelle et présente aussi
tous les paquets disponibles. Les installations directes existantes peuvent rechercher cette version dans les
paramètres de Mise à jour logicielle de Kavor. Aucune migration manuelle des données du Workspace n'est nécessaire ;
le Node WebBrowser est nouveau dans cette version et les données Canvas existantes restent compatibles.

- Windows x64 est disponible dans Microsoft Store ou sous forme d'installateur NSIS assisté par Utilisateur.
  Microsoft signe et met à jour les installations Store. L'installateur direct reste non signé ; Microsoft
  SmartScreen peut donc demander une confirmation explicite.
- macOS 13+ propose des DMG distincts pour Apple Silicon et Intel, signés avec l'Apple Developer ID de Kavor et
  notariés par Apple. Les mises à jour automatiques utilisent le ZIP correspondant à l'architecture et conservent le
  DMG manuel comme solution de repli.
- Linux x64 propose des paquets AppImage et DEB. AppImage prend en charge les mises à jour gérées par Kavor avec un
  redémarrage coordonné explicite ; les mises à jour DEB s'installent manuellement depuis la page de téléchargement.

## Limitations connues

- Les Nodes WebBrowser utilisent le Profil de Navigateur dédié et partagé de Kavor ; ils ne réutilisent pas le
  profil, les extensions, l'historique ni les cookies du Chrome externe de l'Utilisateur. Supprimer un Node n'efface
  pas les données de site partagées ; les paramètres globaux de Kavor permettent d'effacer explicitement le cache,
  les cookies et les données de site.
- Le contrôle par un CodingAgent exige que le Node WebBrowser soit actif sur le Canvas. Les frames intersites isolées
  dans un autre processus Chromium sont signalées comme omises et ne peuvent pas être contrôlées à travers la limite
  de sécurité du guest.
- Les demandes d'autorisation, boîtes de dialogue d'enregistrement, CAPTCHA, passkeys, certificats client et
  authentification du système d'exploitation restent des limites à résoudre par une personne.
- Les paquets Windows ARM64 et Linux ARM64 ne sont pas inclus tant que leurs gates PTY natif, SQLite, confinement de
  processus et runtime empaqueté ne peuvent pas s'exécuter dans des environnements CI correspondants.
- Les téléchargements Windows directs ne disposent pas encore d'un certificat d'éditeur Authenticode ; Microsoft
  signe les paquets Microsoft Store. La disponibilité dans le Store peut suivre la release stable directe après la
  certification indépendante de Microsoft.
