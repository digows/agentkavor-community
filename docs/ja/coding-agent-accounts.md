# CodingAgent Accounts：アカウント、使用状況、ローテーション

## 概要

一つの Specification で Builder と Reviewer が同時に作業し、別の Workspace で三つ目のセッションが動くこともあります。
気づかないうちに同じログインの容量を取り合う必要はありません。**CodingAgent Accounts** で自分のアカウントの容量を確認し、
CodingAgents にどう使わせるかを選べます。

プールはあなた自身のもので、自分の Workspaces 間で共有されます。他の人とアカウントを共有するための機能ではありません。
設定は任意です。provider のネイティブログインだけでも、従来どおり作業を続けられます。

コンピューターにすでにあるログインが主アカウントの **Main** です。provider がメールアドレスを返す場合、Kavor はその
アドレスだけを表示名に使い、識別情報がなければ **Main** と表示します。Kavor でアカウントを追加しても、このログインを
置き換えたり、それを使う provider のアプリをサインアウトさせたりはしません。

Workspace のヘッダーにある **Accounts** グループから始めます。provider にポインターを重ねると概要が表示され、クリックすると
パネルが開きます。使用状況、アカウント、Workspace の選択、設定はこのパネルにまとまっています。Settings に別のアカウント
マネージャーはありません。

## 使用状況

**割合が示すのは残り容量であり、agent の数ではありません。** 複数の CodingAgents が同じアカウントを使い、
その利用枠を同時に消費することがあります。

![Claude Code、Codex、Antigravity、Grok の Accounts 使用状況インジケーターを示す UI 図。](https://media.agentkavor.com/product/2.1.0/coding-agent-accounts/header.118710635e3f.png)

参照スクリーンショットに記録された値を使った UI 図です。provider から新たに取得した使用状況ではありません。

### ヘッダーの概要を読む

- 各インジケーターは provider 固有の色を使い、アカウントの全体的な利用枠を短い期間から順に二つまで表示します。
  五時間枠と週間枠があるアカウントではその二つを表示し、月間枠しかないアカウントに架空の五時間枠を追加しません。
  異なるアカウントの割合を合算することもありません。
- その Workspace で複数のアカウントを使用中の場合、いずれかの利用枠の残り容量が最も少ないアカウントを概要に表示します。
  ホバー表示で使用中のアカウントと各利用枠を確認できます。
- その provider を使う CodingAgents がいない場合、インジケーターは薄くなり、その Workspace の Automatic が選択できる
  アカウントのうち、把握できている範囲で最も余裕のあるものを示します。すでに選択済みという意味ではありません。
- **+N** は、その Workspace の自動選択に使える、容量が判明している他のアカウントの数です。専用の予約ではなく、
  他の CodingAgents が使っているアカウントも含まれる場合があります。**+N?** は未取得の読み取りがあることを示します。
  アカウントが一つしかない provider には予備の数を表示しません。
- 利用枠がローテーションのしきい値に達すると、その枠が琥珀色になります。その Workspace の Automatic が使えるすべての
  アカウントについて、設定したしきい値以上だと確認できた場合は、インジケーター全体が淡い赤になります。
  これは容量の情報であり、作業を禁止するものではありません。

### 利用枠と読み取りを確認する

パネルには、各利用枠の残り容量と次のリセット時刻が表示されます。モデル固有の枠はアカウントの詳細にあり、全体の
インジケーターには含まれません。**More** を開くと、**Read** の時刻、プラン、credits、繰り越し resets など、
provider が実際に返した情報を確認できます。

表示中の読み取りは定期的に更新されます。更新中も、最後の有効な値が実際の取得時刻とともに残ります。パネルを閉じて開き直しても、
古いデータが新しい観測にはなりません。取得に失敗した場合は利用不可の状態やサインインの案内を表示し、最後の有効な割合を
架空の値で置き換えません。provider セレクターの横にある **Refresh** で更新を要求できます。

**Unavailable** や **—** は 0% でも 100% でもありません。不明な読み取りだけでは、容量切れやログインの期限切れを
確認できません。エラーと時刻を確認し、更新を試すか、案内がある場合に再度サインインしてください。使用状況の取得に
失敗しても、アカウント追加や再サインインの操作は隠れません。

| Provider | 表示できる情報 |
| --- | --- |
| **Codex** | 一次・二次の利用枠、それぞれの期間と resets、モデル別の適用範囲、返された場合の credits と繰り越し resets。期間はアカウントによって異なります。 |
| **Claude Code** | セッションや週間など、ネイティブの使用状況から認識できた利用枠と、その割合、resets。ローカルの token 数や費用統計を quota として扱いません。 |
| **Grok** | credits の使用状況、期間と更新時期、返された場合のプランと前払い残高。 |
| **Antigravity** | CLI が報告するグループや buckets の残り容量と resets。 |
| **OpenCode** | この監視の対象外です。使用状況は harness に設定した provider に依存します。 |

取得には provider のネイティブな経路を使い、モデルに作業を依頼しません。残高の照会は、その残高の消費を許可することではありません。

## アカウント

### アカウントを追加して認証する

1. 対応する provider、**Codex**、**Claude Code**、**Grok** のいずれかのパネルを開きます。
2. **Add account** を使い、`Trabalho` のような分かりやすい名前を付けて **Add account and sign in** で確定します。
3. provider のページでネイティブのサインインを完了し、必要に応じて表示されたコードを使います。自分で開始したフローに対して
   認証用アドレスが一度だけ開きます。CLI が自分でブラウザーを開く provider では、Kavor が二つ目のタブを開くことはありません。
4. 認証状態と使用状況を確認します。**ブラウザーが開いたことは、サインイン完了を意味しません。**
5. 新しいアカウントを自動選択に含めるには、使いたい Workspace で参加を有効にします。追加直後はすべての Workspaces で
   Automatic の対象外です。グローバルプールに追加しただけでは有効になりません。

Kavor は追加したアカウント用に分離したプロファイルを準備します。認証情報はそのアカウントの CLI が使うストレージにあり、
Kavor のデータベースには保存されません。Main のネイティブログインは元の場所に残ります。

期限切れのログインには **Sign in again** を使います。管理対象のアカウントでは認証状態を判定できない場合にもこの操作を
提供しますが、不明な読み取りが期限切れの確認に変わるわけではありません。再試行を含め、クリックしてサインインを開始するたびに、
認証用アドレスが利用可能になった時点で一度だけ開きます。開けなかった場合は **Continue provider sign-in** を手動で使ってください。
パネルの再表示や保留中の操作の復元だけで、タブが自動的に開くことはありません。

### Main はログインのコピーではない

Main は、provider が保存している元の場所のネイティブログインをそのまま使います。パネルには Main のサインイン、サインアウト、
削除の操作はありません。provider のツールで管理してください。Kavor の外でネイティブのアカウントを変更すると、Main はその
ログインを表すようになり、以前のアカウントを復元する選択肢は提供されません。

Codex の API key のように、識別情報や使用データがないネイティブログインも従来どおり動作しますが、自動ローテーションには
参加しません。Kavor が認証情報を読み取って識別情報を推測することもありません。

### サインアウトと削除は異なる

**Sign out** はアカウントを一覧に残し、再度サインインできるようにします。**Remove account** は一覧から取り除き、
Kavor が管理する分離プロファイルを削除します。Main のログインや共有のセッション履歴は削除しません。

使用中の CodingAgents がいる場合、Kavor は影響を受けるものを表示して確認を求めます。変更はターン間の安全な境界と、
旧プロセスの解放を待ちます。そのアカウントへの固定選択は Automatic に戻り、Workspace の既定アカウントだった場合は
既定が Main に戻ります。他のアカウントがなければ、実行経路はネイティブログインを使います。

## 個人設定のコピー

アカウントを追加すると、provider のネイティブ環境にある個人設定の**初期コピー**を受け取ります。各アカウントで設定、skills、
MCPs を一から用意し直す必要を減らすためです。対象は provider とコピー元に存在する内容によって異なります。

| Provider | コピーする内容 |
| --- | --- |
| **Codex** | 設定、profiles、個人用 MCPs、カスタム providers を含む `config.toml`、`hooks.json` の個人用 hooks、`AGENTS.md`、`skills`、`plugins`、`rules`、`prompts` ディレクトリ。`forced_chatgpt_workspace_id` はコピーしません。 |
| **Claude Code** | 個人用 statusline と hooks を含む `settings.json`、`keybindings.json`、`CLAUDE.md`、`skills`、`plugins`、`rules`、`agents`、`commands` ディレクトリ。`.claude.json` はファイル全体ではなく個人用 MCPs だけをコピーします。 |
| **Grok** | 設定と個人用 MCPs を含む `config.toml`、`AGENTS.md`、`skills`、`plugins`、`rules`、`hooks` ディレクトリ。 |

**これらの設定に埋め込まれたシークレットもコピーされます。** MCPs の環境変数の値、固定 HTTP ヘッダー、これらのファイルに
書かれたカスタム providers のキーも含みます。ファイルのアクセス権は維持され、これらの値をログや Kavor データベースに
保存することはありません。

**ネイティブログイン、認証ファイル、Keychain の項目、アカウントの識別情報は一切コピーされません。** 追加したアカウントは
自分自身のログインが必要です。Kavor が所有する連携設定も引き継ぎません。そのアカウント用の連携は Kavor が準備します。

これはコピーであり同期ではありません。後から Main に追加した MCP は、使用したい他のアカウントにも設定してください。
追加したアカウントを変更しても Main は変わらず、再サインインしても設定は再コピーされません。

準備中に設定エラーが報告されたら、示された個人用の TOML または JSON を確認してから再試行してください。
修復のために認証ファイルをコピーしたり、ネイティブプロファイル全体を削除したりしないでください。

## アカウントの切り替え

### Workspace ごとの動作を選ぶ

CodingAgent の設定で **Manual** を選ぶと、その Node のアカウントを固定し、Workspace の方針より優先します。
**Auto (Automatic)** の CodingAgent は、その provider に対する Workspace の選択に従います。

Workspace の Accounts パネルでは次のように動作します。

- **Auto Rotate** がオンの場合、参加スイッチで Automatic が使えるアカウントを決めます。同じプールを使っていても、
  各 Workspace は自分の選択を持ちます。参加していないアカウントも表示されたままで、CodingAgent で手動選択したり、
  他の Workspace で使ったりできます。
- 参加アカウントが一つなら、しきい値に達しても Automatic はそのアカウントを使い続けます。参加がなければ Main の
  ネイティブログインを使い、その Workspace では自動ローテーションしません。
- **Auto Rotate** がオフの場合、単一選択のボタンで Automatic の CodingAgents の既定アカウントを決めます。
  オフにすると既定は Main になり、以前の選択は復元しません。参加設定は、Auto Rotate を再びオンにしたときのために残ります。

Auto Rotate や参加設定の保存は即時ですが、**実行中の agents を再起動したり再配分したりはしません**。参加設定は、
セッションの開始やしきい値によるローテーションなど、次に実際の自動選択が行われる際に適用されます。一方、別の既定アカウントや
別の Manual アカウントを明示的に選ぶと、影響を受ける CodingAgents がターン間の安全な境界で移ることがあります。
実際のアカウントが変わらない agent は再起動しません。

![複数のソフトウェアプロジェクトの Canvas ウィンドウを背景に表示された Kavor Workspace スイッチャー。](https://media.agentkavor.com/releases/1.3.0/multiple-workspaces/overview.baa20506a993.jpg)

独立した Workspaces を別々のウィンドウで開いておけます。アカウントを自動選択の対象にする設定は、各 Workspace の Accounts パネルで行います。

### Automatic が別のアカウントを選ぶ仕組み

既定のしきい値は**使用済み容量 95%** で、**Global rotation preferences** の **Rotate at used capacity (%)** から
調整できます。Kavor は認証、プランの利用資格、選択したモデル、Workspace の参加設定、報告されたすべての利用枠を考慮します。
アカウントを選択可能にするためにモデルを変更することはありません。

現在のアカウントが有効なら維持します。すべての利用枠がしきい値未満の適格なアカウントから選ぶ必要がある場合、
次の順序で優先します。

1. その Workspace の CodingAgents がすでに使っているアカウント。
2. 他の Workspace が使っていないアカウント。
3. 共有している他の Workspaces が最も少ないアカウント。

条件が同じ候補では、容量が最も早く回復するものを優先します。四つの Workspaces と四つの利用可能な適格アカウントがあれば、
これにより各 Workspace に一つずつ配分できます。専用の予約ではなく、必要なら共有できます。Workspace の開閉によって
全体を再配分することはありません。

切り替えは**ターン間**に別のアカウントで harness を再起動し、同じネイティブセッションと履歴を再開します。Node は待機、選択、
再起動、再開という実際の段階を示します。待機表示は、まだ使えるターミナルをブロックしません。CLI の再起動中はターミナルを閉じ、
セッションの準備ができると再び開きます。切り替え成功時にはシステム通知を出しません。通知は実際の失敗に限り、Workspace と
CodingAgent を示します。

### 容量切れとターンの失敗

**容量の不足や枯渇だけで CodingAgent を一時停止したり、メッセージをブロックしたり、ターミナル入力を無効にしたりはしません。**
容量のある代替アカウントがなければ、現在のアカウントに留まります。Automatic で最初に開く際、容量のある適格アカウントがなければ
Main を使い、その状況を伝えます。ターンの実際の制限と課金は、引き続き provider が適用します。

ログインの期限切れが確認されたアカウントは、自動選択の対象から外れます。ネットワーク障害や不明な読み取りでは期限切れを
確認できません。この動作が Manual の選択を上書きすることもありません。

**Codex と Claude Code** では、アカウントの quota が原因だと provider が確認したターンの失敗について、同じ Automatic の
規則を満たし、安全に再送できる場合に別のアカウントで再開できます。配信が不確実な場合、認証、rate limit、全体的な過負荷、
原因不明の失敗は再送を許可する根拠になりません。**失敗した Grok のターンは自動再送しません。** ネイティブの信号では quota と
rate limit を区別できないためです。使用量のしきい値によるローテーションは引き続き利用できます。

### Credits と繰り越し resets

**Allow spending credits** と **Allow spending banked resets** は別々の権限で、既定ではオフです。Kavor による選択と
ローテーションを制御するもので、残高が見えても有効にはなりません。credits がオフの場合、設定したしきい値に達したアカウントは、
残高があるという理由で自動選択の資格を得ません。実行中のセッションを中断したり、Manual の選択を変えたりはしません。

**これらの設定はターン内のネイティブな課金を止めません。** アカウントの支出上限と有料消費は provider 自身の設定で
管理してください。Kavor は credits を購入せず、そのログインの課金設定も変更しません。

繰り越し resets とその有効期限は、報告された場合にだけ表示します。繰り越し reset の消費は検証されていません。
残高や設定があることを、消費操作が確実に行えるという意味に解釈しないでください。

## CodingAgents 向けのツール

CodingAgent は認証情報を受け取らずに、あなたのアカウントを照会できます。

- `kavor_coding_agent_account_list_usage` はグローバルプールとネイティブログインを、利用枠、resets、利用資格、観測時刻と
  ともにページングして取得します。provider で絞り込めます。
- `kavor_coding_agent_account_request_change` は、呼び出し元の CodingAgent の**自分自身のアカウント**をターン終了時に
  切り替えるよう要求します。Automatic と、その Workspace で許可されたアカウントの範囲を尊重します。

Manual では要求を拒否し、要求しても適格な代替アカウントがあるとは限りません。これらのツールでは、他の CodingAgent の
アカウントの切り替え、サインイン、アカウント削除、支出権限の変更、tokens へのアクセスはできません。

例：

> 選択を一切変えずに、私のアカウントの利用枠と回復時刻を比較してください。あなた自身のセッションの切り替えを勧める場合は、
> どの読み取りに基づく提案なのか説明し、私の Manual の選択を尊重してください。

## Agent Kavor のコマンド

有効な Channel からの利用も含め、**Agent Kavor** の会話におけるコマンドは、選択中の Workspace を操作します。
制御を解釈するためのモデルのターンは必要ありません。Kavor が実際に表示する名前を使ってください。

```text
/accounts
/accounts codex
/account
@Reviewer /account "Trabalho"
@Reviewer /account auto
/autorotate codex off
/autorotate codex on
/status
```

- `/accounts [provider]` は Workspace の使用状況、回復時刻、予備アカウントの概要を表示します。すべてのアカウントの完全な
  エクスポートではありません。結果がさらにある場合や読み取りが不明な場合は、その制限を示してパネルへ案内します。
- `/account [@Nome]` は選択中または指定した agent のアカウントとモードを照会します。アカウント名かメールアドレスを
  追加すると固定し、`auto` で Automatic に戻します。空白を含む名前は引用符で囲んでください。
- `/autorotate [provider] on|off` はその Workspace の Auto Rotate を切り替え、実行中の agents は移しません。
  provider を省略すると既定の CodingAgent の provider を使います。既定の agent がなければ provider を指定する必要があります。
- `/status` はアカウントと全体的な利用枠も表示し、`/help` は利用できる制御と例を示します。

別のアカウントへの固定は、desktop と同じ検証、安全な境界、フィードバックに従います。コマンドへの返答は、再開の完了を
証明するものではありません。アカウント追加、サインイン、サインアウト、削除、参加設定の変更、Workspace の既定アカウントの
選択は、引き続き desktop パネルで行います。Channel の認可規則も変わりません。

制御を使う前に、[Agent Kavor と Channels](./agent-kavor.md) で Workspace と宛先の選び方を確認してください。

## provider ごとの対応と制限

- **Codex、Claude Code、Grok** は管理対象のアカウントと、セッションの継続性を保つ切り替えに対応します。アカウントの
  プランとモデルが実行を許可している必要があります。分離した設定を用意しても、対象外のプランが利用可能になるわけではありません。
- **Grok** はネイティブアカウントの識別情報を返しません。Main はその中立的な名前のままで、プランや残高からメールアドレスを
  推測しません。ターン再送の例外は前述のとおりです。
- **Antigravity** はコンピューターのアカウントの監視に対応しますが、プール、アカウント切り替え、本ガイドで説明する
  設定コピーには対応しません。
- **OpenCode** は、ここで説明する監視とアカウント管理の対象外です。制限は harness 自身に設定された provider に依存します。
- 識別情報や使用状況が返されないログインも、quota を作り上げたり自動ローテーションを有効にしたりせず、ネイティブな経路で
  利用できます。情報や利用枠はアカウントと認証方式によって異なる場合があります。
- データがないことは残高ゼロを意味しません。ネイティブ形式の変更で観測できなくなる場合があります。quota が尽きたと
  判断する前に、時刻、メッセージ、ログインを確認してください。

これらのアカウントで作業を組み立てるには、[CodingAgent ガイド](./coding-agent.md) と
[agents と役割の分け方](./agents-and-roles.md)へ進んでください。
