# Kavor 1.7.1

## 主な変更

- Electron、Chromium、React、UI ツールチェーン、ランタイム依存関係を互換性のある安定版に更新します。
  この hotfix は既存の Canvas と CodingAgent のワークフローを維持し、実験的なインターフェースは公開しません。

## 修正

- Workspace を切り替えた後の WebBrowser のネイティブなマウス・キーボード入力を復元します。
  保持された稼働中のページを再読み込みせず、ブラウザーの対話的な操作部品も妨げません。
- WebBrowser のポップアップを閉じる際に、所有元ページのポップアップ状態をクリアし、その枠を除去します。
  これにより次のポップアップを開けるようになり、置き換えられた新しいポップアップを誤ってクリアしません。
- 明るい閲覧モードでの Markdown の色を修正します。見出し、リンク、コード、引用、表が対象です。
  明るい閲覧モードと暗い閲覧モードの切り替え時に、コンパクト表示と通常表示で一貫したスタイルを適用します。
- 依存関係の更新後も、Trigger の単発スケジュールの時刻を分単位の精度で保持します。
- 監視対象の Workspace パスをリテラルとして扱い、glob 構文を展開せずに、新規ディレクトリの再帰的な検出を維持します。
- Workspace パッケージのビルド、ネイティブ依存関係の再ビルド、パッケージに含まれる第三者通知の生成において、
  pnpm のネイティブ実行ファイルとの互換性を復元します。
- 対象の gRPC と FTP の依存関係を更新し、レビュー済みの CodingAgent tools schema 契約を維持します。

## インストール

<https://download.agentkavor.com> から Kavor をダウンロードできます。
既存の直接インストール版は Software Update 設定からこのリリースを確認できます。
Workspace データの手動移行は不要です。

- Windows x64 は Microsoft Store、またはユーザー単位の対話式 NSIS インストーラーで提供します。
  Store 版は Microsoft が署名・更新します。直接配布のインストーラーは引き続き未署名のため、
  Microsoft SmartScreen で明示的な確認が必要になる場合があります。
- macOS 13+ では Apple Silicon と Intel 向けに個別の DMG を提供し、Kavor の Apple Developer ID で署名して
  Apple の公証を受けています。自動更新は対応するアーキテクチャの ZIP を使用し、DMG による手動更新も維持します。
- Linux x64 では AppImage と DEB を提供します。AppImage は Kavor 管理の更新と明示的に調整された再起動に対応し、
  DEB の更新はダウンロードページから手動でインストールします。

## 既知の制限

- 上流の `braces` 依存関係に関するセキュリティ勧告には、公開済みの修正パッチがまだありません。
  Workspace の再帰的な監視では glob 展開を無効にしていますが、これは緩和策であり、依存関係の修正ではありません。
- Kavor 専用の共有 Browser Profile はローカル開発を支援するため、すべてのサーバー証明書を受け入れます。
  悪意のあるネットワークは、このプロファイルで開くサイトやユーザーがサインインするサイトになりすますことができます。
  Kavor アプリケーションのセッションは Chromium の通常の証明書検証を維持します。
- WebBrowser Nodes はユーザーの外部 Chrome のプロファイル、拡張機能、履歴、cookies を再利用しません。
  Node を削除しても共有サイトデータは消えません。Kavor のグローバル設定からキャッシュ、cookies、サイトデータを
  明示的に消去できます。
- 別の Chromium プロセスに隔離されたクロスサイト frame は省略されたものとして報告され、
  guest のセキュリティ境界を越えて制御できません。
- Windows ARM64 と Linux ARM64 のパッケージは、対応する CI 環境でネイティブ PTY、SQLite、プロセス封じ込め、
  パッケージ済みランタイムの gates を実行できるようになるまで含まれません。
- Windows の直接ダウンロード版には、まだ Authenticode 発行者証明書がありません。
  Microsoft Store パッケージは Microsoft が署名します。Store での公開は Microsoft の独立した認証が完了するまで、
  直接配布の stable リリースより遅れる場合があります。
