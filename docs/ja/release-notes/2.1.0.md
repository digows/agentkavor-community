# Kavor 2.1.0

## 主な変更

- **自分のアカウントを一か所で。** CodingAgent Accounts は、providers の利用枠、残り容量、回復時刻を Workspace の
  ヘッダーとアカウントパネルにまとめます。Codex、Claude Code、Grok の個別アカウントを追加・管理し、CodingAgent の
  アカウントを選ぶか、Automatic による選択を使えます。ネイティブログインは Main のままで、Kavor で追加したアカウントが
  provider のアプリのログインを置き換えることはありません。
- **Workspaces 間で容量を配分。** Automatic は各 Workspace の参加アカウント、モデルの互換性、使用量のしきい値を
  考慮します。可能な場合は異なる Workspaces に別々のアカウントを優先し、ターン間の安全な境界で切り替えます。
  Manual の選択が優先されます。報告された容量の不足や枯渇だけで CodingAgent を一時停止したり、ターミナル入力を
  ブロックしたりはしません。
- **Agent Kavor からアカウントを制御。** 選択中の Workspace で `/accounts`、`/account`、`/autorotate` を使えます。
  有効な Channel からも利用でき、`/status` にも CodingAgent のアカウントと使用状況が表示されます。これらの構造化された
  コマンドは desktop と同じ制御を使い、振り分けのためのモデルのターンは不要です。アカウント追加とサインインは
  引き続き desktop で行います。

## 修正

- 表示中のアカウントの使用状況を定期的に更新し、失敗した観測を再試行します。最後の有効な割合を保ちながら、
  利用不可の状態やサインインの案内を明示します。取得に失敗してもアカウント追加と再サインインを利用できます。
- agents 間のメッセージ配信と、Grok、OpenCode、Antigravity の入力の利用可能性を改善します。中断された送信、
  フォーカスのない Grok 入力欄、OpenCode の横幅の広いレイアウト、長いネイティブ履歴に対応します。人間の下書きと
  ネイティブの質問に対する保護は維持し、配信が不確実な場合は自動で重複送信しません。
- CodingAgents のターミナルの復元、サイズ変更の処理、Node を再表示または再接続した際の活動表示を改善します。
  provider の受動的な通知を、進行中の作業と混同しなくなります。
- CodingAgents の失敗通知で provider の制限、過負荷、認証、その他の失敗を区別し、より役立つ案内にします。
  Channels の返答に未加工の診断情報は公開しません。
- ポインターが埋め込みページに入ったら Browser Node のサイズ変更を止め、そのページとの操作を保ちます。
- Workspace の Git 操作をフッターへ移し、Workspace のリポジトリと、選択中の Node のリポジトリまたは worktree を
  引き続き区別します。
- Electron と同梱の依存関係を、セキュリティ修正を含むものに更新します。

## インストール

<https://download.agentkavor.com> から Kavor をダウンロードしてください。既存の直接インストールでは Software Update
設定からこのバージョンを確認できます。Kavor でアカウントを追加しなくても、provider のネイティブログインは引き続き
利用できます。データベースの更新は、バックアップを伴う Kavor の移行フローを使います。

- **Windows x64：** Microsoft Store、またはユーザー操作を伴う NSIS インストーラー。Store 版の署名と更新は Microsoft が
  提供します。直接配布版はまだ発行元署名がないため、SmartScreen が明示的な確認を求める場合があります。
- **macOS 13+：** Apple Silicon と Intel 用の個別の署名・公証済み DMG。自動更新は該当アーキテクチャの ZIP を使い、
  手動インストール用の DMG も引き続き利用できます。
- **Linux x64：** AppImage と DEB。AppImage は明示的な協調再起動を伴う Kavor 管理の更新に対応し、DEB はダウンロード
  ページから手動で更新します。

## 既知の制限

- アカウントの使用状況と識別情報は、各 provider が返す内容に依存します。Antigravity は使用状況の監視に対応しますが、
  アカウントプールは提供しません。OpenCode の使用状況は設定した provider に依存し、この監視の対象外です。
  Grok はネイティブの識別情報を返しません。読み取れない情報は使用量ゼロではなく、利用不可として表示します。
- Grok は、確認済みの quota による失敗と一般的な rate limit を区別できません。そのため、失敗した Grok のターンを
  別のアカウントで自動再送しません。使用量のしきい値によるローテーションは引き続き利用できます。
- 繰り越し resets の残高は provider が返す場合に表示できますが、繰り越し reset の消費は検証されていません。
  credits と resets の設定が制御するのは Kavor のアカウント選択であり、provider で進行中のターン内の課金ではありません。
- WhatsApp には連携済みアカウント、ネットワーク、起動して認証済みの Kavor desktop と、スリープしていないコンピューターが
  必要です。Meta がホストする WhatsApp Business API ではなく、連携済みデバイスを使います。desktop 上の承認は
  引き続きあなたの操作が必要です。
- 共有 Browser Profile はローカル開発のため任意のサーバー証明書を受け入れます。悪意あるネットワークは、この
  プロファイルで開いたサイトになりすます可能性があります。アプリ自身のセッションは通常の証明書検証を維持します。
  Browser Nodes は外部 Chrome のプロファイルや拡張を再利用しません。別プロセスの frames は、埋め込みページの
  制御境界の外にあります。
- Windows ARM64 と Linux ARM64 パッケージは含まれません。Microsoft Store での公開は Microsoft の独立した認証により、
  直接配布より遅れる場合があります。
