# Kavor 2.0.0

> 2026 年 10 月 16 日の編集上の改訂：Agent Kavor と Browser の説明を明確にしました。2.0.0 のバイナリは変更しません。
> [元のリリースノート](https://github.com/digows/agentkavor-community/blob/285143eb2012de9e702c2cd80bb5d5f1a75ea8fc/docs/ja/release-notes/2.0.0.md)
> も引き続き参照できます。この改訂でアプリに組み込まれたコピーは変更されません。

## 主な変更

- **WhatsApp から Agent Kavor へ。最初の公開 Channel です。** 個人チャットや Workspace ごとの専用グループで
  ローカル agents と会話できます。コンテキストと CodingAgent を選び、進行状況の確認、質問への回答、添付ファイルの
  交換を行えます。上部バーの Channels 設定でアカウントを連携すると、Workspace Channels が表示され、設定は自動保存されます。
  ペアリング、再接続、コマンド・状態・キャンセル・エラーのフィードバックを改善し、ネイティブな再実行でも
  Motion Photo の元のコンテンツと対応関係を保持します。
- **CodingAgents の協業。** provider ネイティブの送信、ターン終了後の配信、許可された場合の明示的な中断が
  Connection Guardrails に従い、人の下書きを保護します。接続された agents は、件数を制限したページ分割済みの履歴から、
  他の agents が完了したターンを読むこともできます。
- **表示中の Canvas の外でも動く Browser。** 接続された agents はバックグラウンドの WebBrowser タブを操作できます。
  Start、Shutdown、音声ミュートを明示的に制御でき、UI のライフサイクルが変化しても停止の選択、保存済みタブ、
  共有サイトデータを保持します。
- **必要に応じたリソース利用。** 補助プロセスは必要なときに起動し、Workspace、Terminal、CodingAgent、Browser の
  永続化された状態を失わずに非アクティブなリソースを解放します。PTY と補助プロセスの後片付けも改善しました。
- **書体とビジュアルの刷新。** desktop に Inter と Geist Mono を採用し、アプリのビジュアルを調整して、
  macOS アプリアイコンの透過を復元します。

## 修正

- CodingAgent のネイティブな起動オプションを保持します。モデル、権限、セッション、作業ディレクトリの明示的な引数を含み、
  ユーザーの選択を黙って置き換えません。
- Grok のターン完了と検証済みのパッシブなセッション読み取りを修正し、Workspace ウィンドウ間でのネイティブな
  メッセージ配信の対応付けと通知の確認処理を改善します。
- CodingAgent のネイティブな質問を表示し、OS 通知のタイトルに発生元の Workspace を含めることで、
  複数 Workspace の並行作業を識別しやすくします。

## インストール

<https://download.agentkavor.com> から Kavor をダウンロードできます。
既存の直接インストール版は Software Update 設定からこのリリースを確認できます。
Workspace データベースの更新は、バックアップを伴う Kavor の移行手順で行われます。

- Windows x64 は Microsoft Store、またはユーザー単位の対話式 NSIS インストーラーで提供します。
  Store 版は Microsoft が署名・更新します。直接配布のインストーラーは引き続き未署名のため、
  Microsoft SmartScreen で明示的な確認が必要になる場合があります。
- macOS 13+ では Apple Silicon と Intel 向けに個別の DMG を提供し、Kavor の Apple Developer ID で署名して
  Apple の公証を受けています。自動更新は対応するアーキテクチャの ZIP を使用し、DMG による手動更新も維持します。
- Linux x64 では AppImage と DEB を提供します。AppImage は Kavor 管理の更新と明示的に調整された再起動に対応し、
  DEB の更新はダウンロードページから手動でインストールします。

## 既知の制限

- Terminal の OSC 8 ハイパーリンクが、すでにポインターのある行に出力された場合、開く前に別の行へポインターを移し、
  戻す必要があることがあります。上流 xterm のホバーキャッシュに関するこの制限は、本リリースでも残っています。
- 本番依存関係の監査では、上流の [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) と
  [sprintf-js](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) に対する未解決のサービス拒否の勧告が報告されています。
  これらの依存バージョンは Kavor 1.7.1 にも含まれていました。Workspace の再帰的な監視は braces を使う経路で
  glob 展開を無効にしていますが、これは緩和策であり、依存関係の修正ではありません。
- WhatsApp には、連携済みアカウント、ネットワーク接続、desktop 上で認証済みセッションで稼働する Kavor が必要です。
  リンク済みデバイスによる連携は Meta がホストする WhatsApp Business API ではなく、WhatsApp アカウントの制限は
  引き続き Meta が管理します。
- Kavor 専用の共有 Browser Profile はローカル開発を支援するため、すべてのサーバー証明書を受け入れます。
  悪意のあるネットワークは、このプロファイルで開くサイトやユーザーがサインインするサイトになりすますことができます。
  Kavor アプリケーションのセッションは Chromium の通常の証明書検証を維持します。
- WebBrowser Nodes はユーザーの外部 Chrome のプロファイル、拡張機能、履歴、cookies を再利用しません。
  Node を削除しても共有サイトデータは消えません。Kavor のグローバル設定からキャッシュ、cookies、サイトデータを
  明示的に消去できます。
- 別の Chromium プロセスに隔離されたクロスサイト frame は省略されたものとして報告され、
  guest のセキュリティ境界を越えて制御できません。
- Windows ARM64 と Linux ARM64 のパッケージは含まれません。Windows の直接ダウンロード版には、まだ Authenticode
  発行者証明書がありません。Microsoft Store パッケージは Microsoft が署名します。Store での公開は Microsoft の
  独立した認証が完了するまで、直接配布の stable リリースより遅れる場合があります。
