# Kavor 2.1.0

## Highlights

- **Your accounts, in one place.** CodingAgent Accounts brings provider usage windows, remaining capacity and renewal
  times into the Workspace header and account panel. Add and manage separate Codex, Claude Code and Grok accounts,
  choose an account for a CodingAgent, or use Automatic selection. Your existing native login remains the Main account;
  accounts added in Kavor do not replace the login used by the provider's own apps.
- **Share capacity across your Workspaces.** Automatic selection considers the accounts participating in each
  Workspace, model compatibility and your usage threshold. It prefers separate accounts for different Workspaces
  when available and changes accounts at a safe turn boundary. Manual choices take precedence. Low or exhausted
  reported capacity alone never pauses a CodingAgent or blocks its terminal input.
- **Account controls through Agent Kavor.** Use `/accounts`, `/account` and `/autorotate` in the selected Workspace,
  including through an enabled Channel. `/status` also shows the CodingAgent's account and usage. These structured
  commands use the same account controls as the desktop, without a routing model turn. Adding accounts and signing
  in remain desktop actions.

## Fixes

- Refreshes visible account usage periodically, retries failed observations and preserves the last valid percentages
  with explicit unavailable or sign-in feedback. Adding an account and signing in again remain accessible when a
  usage query fails.
- Improves peer-message delivery and input readiness in Grok, OpenCode and Antigravity, including interrupted
  submissions, an unfocused Grok composer, wide OpenCode layouts and long native transcripts. Human drafts and native
  questions keep their input guards; uncertain submissions are not automatically duplicated.
- Improves CodingAgent terminal restoration, resize handling and activity presentation when reopening or reconnecting
  a Node. Passive provider notifications no longer masquerade as active work.
- Makes CodingAgent failure feedback more useful by distinguishing provider limits, overload, authentication and
  other failures without exposing raw provider diagnostics in Channel replies.
- Stops Browser Node resizing when the pointer enters the embedded page, preserving page interaction.
- Moves Workspace Git controls to the footer and keeps the Workspace repository distinct from a selected Node's
  repository or worktree.
- Updates Electron and bundled dependencies with security fixes.

## Installation

Download Kavor from <https://download.agentkavor.com>. Existing direct installations can check for this version in
Software Update settings. Existing native provider logins remain usable without adding an account in Kavor.
Database upgrades use Kavor's migration flow with a backup.

- **Windows x64:** Microsoft Store or the user-assisted NSIS installer. Microsoft signs and updates Store installations.
  The direct installer still has no publisher signature, so SmartScreen may require explicit confirmation.
- **macOS 13+:** separate, signed and notarized DMGs for Apple Silicon and Intel. Automatic updates use the ZIP for the
  matching architecture; the DMG remains available for manual installation.
- **Linux x64:** AppImage and DEB. AppImage supports Kavor-managed updates with an explicit coordinated restart;
  DEB updates are installed manually from the download page.

## Known limitations

- Account usage and identity depend on what each provider exposes. Antigravity supports usage monitoring, not an
  account pool; OpenCode usage depends on its underlying provider and is not included in account monitoring.
  Grok does not expose a native account identity. An unreadable observation is shown as unavailable, not as zero usage.
- Grok does not distinguish a confirmed account quota failure from a general rate limit, so failed Grok turns are
  not automatically re-sent on another account. Threshold-based account rotation remains available.
- Banked-reset balances can be displayed when reported by the provider; spending a banked reset has not been verified.
  Credit and banked-reset preferences govern Kavor's account selection, not billing inside a provider's running turn.
- WhatsApp requires a linked account, network access and an authenticated Kavor desktop running on an awake computer.
  It uses linked devices, not Meta's hosted WhatsApp Business API. Desktop approvals still require you.
- The dedicated shared Browser Profile accepts any server certificate for local development. A hostile network can
  impersonate sites opened in that profile. The app session keeps normal certificate validation. Browser Nodes do not
  reuse an external Chrome profile or extensions; cross-process frames remain outside the guest control boundary.
- Windows ARM64 and Linux ARM64 packages are not included. Microsoft Store availability may follow direct publication
  because of Microsoft's independent certification.
