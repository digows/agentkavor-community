# Kavor 2.4.2

## Highlights

- **Skip trust prompts:** a per-CodingAgent startup preference, enabled by default, starts supported harnesses without
  asking to trust the selected folder or its hooks. Turn it off in Startup settings and apply it on the next start.
  Explicit native arguments still take precedence; tool permissions and sign-in remain separate. Trusting the folder
  also lets the harness load its project hooks and other native project configuration.
- **Diagram panel organization:** create folders and files from the Diagram panel and manage them alongside the
  existing documentation tree, with clearer feedback when an action cannot be completed.
- **Canvas content loaded when needed:** text editors, language support and the Connection Inspector load on demand,
  while retaining their existing editing and inspection behavior.

## Fixes

- Canvas drags continue correctly across Diagram previews, and opening a text document at a requested line reveals
  that line on the initial load.
- Windows provider detection and process launches preserve arguments passed through npm `.cmd` and `.bat` launchers,
  including paths with spaces and quoted values.
- Removing a managed Codex account retains the history locations used by its native session index while removing
  account-local credentials and state. This prevents new broken history links; it does not repair older broken links.
- ACP startup reports the original initialization error even when process cleanup also fails.
- Process hosts use dedicated runtime entrypoints, and desktop packages omit two unused Claude SDK entrypoints
  without removing the SDK features used by Kavor.

## Installation

Update through Kavor or use [download.agentkavor.com](https://download.agentkavor.com). macOS packages are
Developer ID-signed and Apple-notarized. Direct Windows installers remain unsigned and may show SmartScreen
warnings; the Microsoft Store remains a separate distribution channel with Store-owned updates.

## Known limitations

- Skip trust prompts does not approve sign-in, tool permissions or a repository's own Claude Code MCP prompt.
  An unrecognized trust screen remains available for the User to answer. OpenCode does not require this preference.
- Diagram engines and resources are obtained on demand. First use may require internet access; external resources
  may still require a connection. draw.io remains view-only, and D2 does not offer TALA.
