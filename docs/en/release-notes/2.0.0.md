# Kavor 2.0.0

> Editorial revision, October 16, 2026: clarifies the presentation of Agent Kavor and Browser without changing
> the 2.0.0 binaries. The [original notes](https://github.com/digows/agentkavor-community/blob/285143eb2012de9e702c2cd80bb5d5f1a75ea8fc/docs/en/release-notes/2.0.0.md)
> remain available; the copy embedded in the application does not change with this revision.

## Highlights

- **Agent Kavor through WhatsApp, the first public Channel.** Talk to your local agents in a personal chat or a
  dedicated group for each Workspace. Choose the context and CodingAgent, follow progress, answer questions, and
  exchange attachments. Link your account through Channels setup in the header; Workspace Channels appears after
  linking, and settings save automatically. The experience includes improved pairing, reconnection, and command,
  status, cancellation, and error feedback, while preserving original Motion Photo content and correlation across
  native replay.
- **CodingAgent collaboration.** Provider-native submission, after-turn delivery, and explicit interruption where
  permitted respect Connection Guardrails and preserve human drafts. Connected agents can also read completed
  peer-session turns through bounded, paginated history.
- **Browser stays active beyond the visible Canvas.** Connected agents can control WebBrowser tabs in the background.
  Start, Shutdown, and audio muting remain under explicit control, preserving shutdown choices, saved tabs, and
  shared site data across UI lifecycle changes.
- **Resources on demand.** Supporting processes start when needed, and inactive resources are released without
  losing persisted Workspace, Terminal, CodingAgent, and Browser state. PTY and supporting-process cleanup has
  also been improved.
- **Refreshed typography and visual identity.** Inter and Geist Mono on the desktop, refined application artwork,
  and restored transparent macOS application icons.

## Fixes

- Preserves native CodingAgent startup options, including explicit model, permissions, session, and working-directory
  arguments, without silently replacing the User's choices.
- Corrects Grok turn completion and qualified passive session reads, and improves native message-delivery
  correlation and notice acknowledgement across Workspace windows.
- Surfaces native CodingAgent questions and includes the originating Workspace in operating-system notification
  titles, making parallel Workspace activity easier to identify.

## Installation

Download Kavor from <https://download.agentkavor.com>. Existing direct installations can check for this release
from Software Update settings. Workspace database upgrades run through Kavor's backed-up migration path.

- Windows x64 is available from Microsoft Store or as the assisted per-User NSIS installer. Microsoft signs and
  updates Store installations. The direct installer remains unsigned, so Microsoft SmartScreen may require explicit
  confirmation.
- macOS 13+ provides separate Apple Silicon and Intel DMGs signed with Kavor's Apple Developer ID and notarized by
  Apple. Automatic updates use the matching architecture-specific ZIP and retain the manual DMG fallback.
- Linux x64 provides AppImage and DEB packages. AppImage supports Kavor-managed updates with an explicit coordinated
  restart; DEB updates are installed manually from the download page.

## Known limitations

- An OSC 8 Terminal hyperlink printed on a line already under the pointer may require moving the pointer to another
  line and back before opening. This upstream xterm hover-cache limitation remains in this release.
- The production dependency audit reports unresolved upstream denial-of-service advisories for
  [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) and
  [sprintf-js](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). These dependency versions were already present in
  Kavor 1.7.1. Recursive Workspace watching disables glob expansion for the braces path; that is a mitigation,
  not a patched dependency.
- WhatsApp requires a linked account, network access, and Kavor running on the desktop with an authenticated session. Its linked-device
  integration is not Meta's hosted WhatsApp Business API; WhatsApp account restrictions remain controlled by Meta.
- Kavor's dedicated shared Browser Profile accepts every server certificate to support local development. A hostile
  network can therefore impersonate sites opened in that profile, including sites where the User signs in. The Kavor
  application session retains Chromium's normal certificate verification.
- WebBrowser Nodes do not reuse the User's external Chrome profile, extensions, history, or cookies. Deleting a Node
  does not erase shared site data; global Kavor settings provide explicit cache, cookie, and site-data clearing.
- Cross-site frames isolated into another Chromium process are reported as omitted and cannot be controlled through
  the guest-scoped security boundary.
- Windows ARM64 and Linux ARM64 packages are not included. Windows direct downloads do not yet have an Authenticode
  publisher certificate; Microsoft Store packages are signed by Microsoft. Store availability may follow the direct
  stable release after Microsoft's independent certification completes.
