# Kavor 1.3.0

## 主要亮点

- 新增用于单次和周期任务的 Schedule Trigger Node。可将 Trigger 连接到一个 CodingAgent 或 Terminal，按保存的
  时区预览后续触发时间，立即暂停或恢复，按需运行，并查看包含错过、阻塞、失败和完成结果的持久触发历史。
- 新增基于同一共享 runtime 的独立 Workspace 窗口。可并排打开不同 Workspace，恢复上次的窗口会话，按
  Workspace 隔离 Terminal 与 CodingAgent 会话，并可选择让 Kavor 保留在系统托盘以及登录时在后台启动。
- 使用获授权 CodingAgent 的直接原子编辑取代 Canvas 提案队列。经过验证的一组 Node、Connection、File 和
  Specification 更改现在会作为一个操作整体提交，或一起回滚。
- 将相连图定义为 CodingAgent 的共享上下文边界。图中可达的 Agent 可交换持久且可检查的消息，而直接
  Connection 上的 Guardrail 仍会限制对应的资源组合。
- 新增由随应用打包的 ripgrep 提供的有界 Workspace 文件搜索、更丰富的文件链接预览，以及通过本地 MCP
  目录公开的 Kavor 官方文档。
- 在 Workspace Header 中统一 CodingAgent、Specification 和 Trigger 状态，并新增“关于”界面，显示已安装版本、
  build 来源、更新、支持、安全和法律信息。

## 修复

- 原生通知激活时复用拥有相关 Workspace 的现有窗口，不再打开重复窗口或切换无关窗口。
- 在打开、关闭、恢复或切换多个 Workspace 窗口时，稳定 provider 环境发现、CodingAgent 启动、PTY Host
  诊断、Terminal 恢复和 PTY 呈现。
- 在切换 Workspace 时保留后台 CodingAgent 的完成与注意信号，并仅在相关工作尚未显示时发送原生通知。
- 串行处理排队的 CodingAgent 消息和 Trigger 投递，避免覆盖人工输入或跳过目标会话已接受的工作。
- Claude Code 暂时不可用时延后 provider 会话重命名，不再让原本可用的会话失败。
- 隔离 Terminal 屏幕跟踪错误，并显示真实的 host 启动失败，不再将其掩盖为通用 timeout。

## 安装

请从 <https://download.agentkavor.com> 下载 Kavor。页面会检测当前平台，同时列出全部可用软件包。现有直接安装
可在 Kavor 的 Software Update 设置中检查此版本。Workspace 数据无需手动迁移；Kavor 会在升级 schema 前备份
受支持的本地数据库。

- Windows x64 使用按用户辅助安装的 NSIS。安装程序目前未签名，Microsoft SmartScreen 可能要求明确确认。
- macOS 13+ 分别提供 arm64 和 x64 DMG。build 使用 ad-hoc 签名但未公证；请遵循下载页的 Gatekeeper 说明。
  Kavor 管理的更新会使用与架构匹配的 ZIP，并在重新验证缓存制品后提供明确的协调重启。手动下载始终可用。
- Linux x64 提供 AppImage 和 DEB。AppImage 支持 Kavor 管理的更新及明确重启；DEB 需要从下载页手动更新。

## 已知限制

- Schedule Trigger 要求 Kavor runtime 正在运行、机器处于唤醒状态、用户已登录且目标会话处于活动状态。Kavor
  未运行期间错过的触发会被记录并提供明确的手动运行操作；它不会在下次启动时自动执行。
- Windows ARM64 和 Linux ARM64 尚待可运行原生 PTY、SQLite、进程限制及打包 runtime gate 的对应 CI 环境。
- Windows 直接下载尚无 Authenticode 发布者证书。
- macOS 尚无 Developer ID 签名和公证。Gatekeeper 可能要求手动确认，替换 ad-hoc build 时 macOS 也可能再次
  请求访问 Keychain 中的 `Kavor Safe Storage`。
- 本版本不通过 Microsoft Store 分发。
