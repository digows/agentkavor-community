# Kavor 2.0.1

## 主要更新

- **让结果主动送到你身边。** 即使在 desktop 会话中，你也可以要求 CodingAgent 将摘要或结果发送到其 Workspace 中
  已启用的对话。agent 会明确选择目标，不需要之前有 WhatsApp 消息。对收到请求的回复仍返回原始对话，不受之后
  Workspace 或默认 agent 变化的影响。这不会转发整个终端，也不会自动发布到所有群组。
- **向 agents 发送音频。** Kavor 会在向目标 CodingAgents 交付请求之前自动准备转录，同时保留原始录音、说明文字和
  接收者选择。转录被标记为从音频生成的文字，可能包含错误。同一请求的所有接收者使用同一个结果。如果准备失败，
  原始对话会收到操作提示，等待中的 agents 不会收到该请求。
- **Channels 状态更紧凑。** 简短通知的上下文与文字放在同一行，按屏幕宽度自然换行。完整回复、问题和长内容保留各自格式。

## 修复

- 保留 Undo 或 Redo 运行期间接受的 Canvas 编辑，避免先前操作完成时覆盖新的历史记录。中途的编辑也会使旧的
  Redo 路径失效。
- 点击 **Restart** 后可看到更新准备状态，准备期间应用保持打开，并尊重文件的保存、丢弃或取消决定。取消关闭或
  准备失败会将控制权交还应用；正常退出不会开始安装。
- 改进 WhatsApp Workspace 群组恢复：**Check group** 检查关联账户能否访问群组，**Remove group link** 只在确认后
  移除关联。群组、手机配对、已接受的历史记录和其他 Workspaces 均保留。临时故障不会自动清除关联。
- 修复 Sticky Note 列表的字体排版、标记对齐和换行。

## 安装

从 <https://download.agentkavor.com> 下载 Kavor。已有的直接安装版本可以在 Software Update 设置中检查此版本。
Workspace 数据库升级通过 Kavor 带备份的迁移流程进行。

- **Windows x64：** Microsoft Store 或需要用户操作的 NSIS 安装程序。Microsoft 为 Store 安装签名并提供更新。
  直接安装程序仍无发布者签名，SmartScreen 可能要求明确确认。
- **macOS 13+：** Apple Silicon 与 Intel 各有已签名并经过公证的 DMG。自动更新使用相应架构的 ZIP，DMG 仍可用于手动安装。
- **Linux x64：** AppImage 与 DEB。AppImage 支持 Kavor 管理的更新，并要求明确的协调重启；DEB 从下载页手动更新。

## 已知限制

- WhatsApp 需要关联账户、网络，以及在保持唤醒的电脑上运行并登录的 Kavor。集成使用关联设备，不是 Meta 托管的
  WhatsApp Business API。desktop 上待处理的审批仍需要你操作。
- 音频转录使用经过身份验证的云端服务，不是完全离线处理。限制为**每段音频 25 MB（25,000,000 字节）**，与附件
  存储限制不同。转录不会把语音变成 Kavor 控制命令，不替代原件，也不会延长上传后七天的访问期限。
- 图片取决于 harness 和模型支持。视频以原始文件尽力交付，不进行自动转换或提取视频帧，不保证每个 CodingAgent 都能理解。
- 如果 Terminal 的 OSC 8 链接打印在指针已停留的行上，受 xterm 悬停缓存影响，可能需要先把指针移到其他行再移回来才能打开。
- [braces](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm) 和
  [sprintf-js](https://github.com/advisories/GHSA-hp3w-g68c-fv3c) 的上游拒绝服务安全公告仍然存在。Workspace 递归监控在
  使用 braces 的路径禁用了 glob 展开；这是缓解措施，不代表依赖已修复。
- 专用且共享的 Browser Profile 为本地开发接受任意服务器证书。恶意网络可能冒充该配置中打开的网站。应用自身会话仍执行
  正常证书验证。WebBrowser Nodes 不复用外部 Chrome 的配置或扩展；删除 Node 不会清除共享网站数据，请在设置中明确清理。
  隔离到其他进程的跨站框架会被标记为省略，无法跨越 guest 安全边界控制。
- 不提供 Windows ARM64 或 Linux ARM64 安装包。Microsoft Store 上线可能晚于直接发布，取决于 Microsoft 的独立认证。
