# Kavor 2.1.0

## 主要变化

- **在同一处管理你的账户。** CodingAgent Accounts 在 Workspace 顶部栏和账户面板中汇集 providers 的使用窗口、
  剩余容量和重置时间。你可以添加与管理独立的 Codex、Claude Code 和 Grok 账户，为某个 CodingAgent 选择账户，
  或使用 Automatic 选择。原生登录仍是 Main 账户；在 Kavor 中添加账户不会替换 provider 应用的登录。
- **在 Workspaces 之间分配容量。** Automatic 选择会考虑每个 Workspace 的参与账户、模型兼容性和使用阈值。
  有可用账户时，优先为不同 Workspaces 使用不同账户，并在轮次之间的安全边界切换。Manual 选择具有优先权。
  仅仅是报告的容量不足或耗尽，不会暂停 CodingAgent 或阻止终端输入。
- **通过 Agent Kavor 控制账户。** 在选定的 Workspace 中使用 `/accounts`、`/account` 和 `/autorotate`，
  也可通过已启用的 Channel 使用。`/status` 还会显示 CodingAgent 的账户与使用情况。这些结构化命令使用 desktop 的
  相同控制，无需模型轮次来路由。添加账户和登录仍在 desktop 中进行。

## 修复

- 定期更新可见账户的使用情况，重试失败的观测，并保留最后有效的百分比，同时明确显示不可用状态或登录指引。
  使用情况查询失败时，添加账户和重新登录仍然可用。
- 改进 agents 之间的消息交付，以及 Grok、OpenCode 和 Antigravity 的输入可用性，涵盖中断的发送、未获焦点的 Grok
  输入框、OpenCode 宽布局和较长的原生历史。人类草稿与原生问题的保护机制保持不变；交付不确定的消息不会自动重复发送。
- 改进 CodingAgents 终端恢复、尺寸调整处理，以及重新打开或重连 Node 时的活动指示。
  provider 的被动通知不再被误认为正在执行的工作。
- 让 CodingAgents 的失败提示更有用，区分 provider 限制、过载、身份验证及其他故障，同时不在 Channels 回复中暴露原始诊断。
- 当指针进入嵌入页面时，停止调整 Browser Node 的尺寸，保留与该页面的交互。
- 将 Workspace 的 Git 控制移至底部栏，并继续区分 Workspace 仓库与所选 Node 的仓库或 worktree。
- 更新 Electron 和随应用分发的依赖，包含安全修复。

## 安装

从 <https://download.agentkavor.com> 下载 Kavor。已有的直接安装可在 Software Update 设置中检查此版本。
无需在 Kavor 中添加账户，provider 的原生登录仍可使用。数据库更新使用 Kavor 带备份的迁移流程。

- **Windows x64：** Microsoft Store 或需用户操作的 NSIS 安装程序。Store 安装由 Microsoft 签名并更新。
  直接安装程序尚无发布者签名；SmartScreen 可能要求明确确认。
- **macOS 13+：** 分别为 Apple Silicon 和 Intel 提供已签名且经过公证的 DMG。自动更新使用对应架构的 ZIP；
  DMG 仍可用于手动安装。
- **Linux x64：** AppImage 和 DEB。AppImage 支持 Kavor 管理的更新，并要求明确协调重启；
  DEB 更新需从下载页面手动安装。

## 已知限制

- 账户使用情况和身份取决于各 provider 返回的信息。Antigravity 提供使用情况监测，不提供账户池；OpenCode 的使用情况
  取决于配置的 provider，不参与这里的监测。Grok 不返回原生身份。无法读取的数据会显示为不可用，而不是零使用量。
- Grok 无法区分已确认的配额故障和一般 rate limit，因此失败的 Grok 轮次不会在其他账户上自动重发。
  按使用阈值轮换仍然可用。
- provider 返回时可以显示累积 resets 的余额；累积 reset 的实际消耗尚未经过验证。
  credits 和 resets 偏好控制的是 Kavor 的账户选择，而不是 provider 正在执行的轮次内的计费。
- WhatsApp 需要已关联的账户、网络，以及在未睡眠电脑上运行并已登录的 Kavor desktop。集成使用关联设备，
  不是 Meta 托管的 WhatsApp Business API。desktop 审批仍然需要你处理。
- 共享 Browser Profile 为本地开发接受任意服务器证书。恶意网络可能冒充在此配置中打开的网站。
  应用自身的会话保留正常证书验证。Browser Nodes 不复用外部 Chrome 的配置或扩展；
  跨进程 frames 不在嵌入页面的控制边界之内。
- 不包含 Windows ARM64 和 Linux ARM64 软件包。Microsoft Store 的可用时间可能晚于直接发布，
  因为它取决于 Microsoft 独立的认证流程。
