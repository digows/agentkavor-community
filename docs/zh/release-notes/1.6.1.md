# Kavor 1.6.1

## 亮点

- 启用选项后，预发布版更新检查会立即使用 Kavor 的公开 prerelease 渠道；手动检查则比较 stable 与
  prerelease 清单，并选择当前可用的最新版本。
- 改进 WebBrowser Node 的 chrome：header 更高且保持稳定，地址栏更易读，加载指示器固定在 header
  内，不再推动页面 viewport。

## 修复

- 防止 WebBrowser 内容在导航开始或结束时发生位移或尺寸变化。
- 恢复 Canvas 工具栏中 Terminal 图标应有的高对比度。
- 统一 Workspace 设置中可折叠区段的图标。
- 加固直接更新交付和 Microsoft Store 提交流程，确保已完成的 Store rollout 在提交下一个包之前完成收尾。

## 安装

请从 <https://download.agentkavor.com> 下载 Kavor。页面会检测当前平台，同时也提供所有可用安装包。
现有直接安装版本可以在 Kavor 的 Software Update 设置中检查此版本。无需手动迁移 Workspace 数据。

- Windows x64 可通过 Microsoft Store 或按用户辅助安装的 NSIS 安装程序获取。Microsoft 会为 Store
  安装签名并提供更新。直接安装程序仍未签名，因此 Microsoft SmartScreen 可能要求明确确认。
- macOS 13+ 分别提供 Apple Silicon 和 Intel DMG，使用 Kavor 的 Apple Developer ID 签名并经过 Apple
  公证。自动更新使用与架构匹配的 ZIP，同时保留 DMG 作为手动安装备选方案。
- Linux x64 提供 AppImage 和 DEB。AppImage 支持由 Kavor 管理并经明确协调重启的更新；DEB 需要从下载页手动更新。

## 已知限制

- WebBrowser Nodes 使用 Kavor 专用的共享 Browser Profile；不会复用用户外部 Chrome 的 profile、扩展、
  历史记录或 Cookie。删除 Node 不会清除共享站点数据；Kavor 的全局设置提供明确的缓存、Cookie 和站点数据清理功能。
- CodingAgent 控制要求 WebBrowser Node 在 Canvas 上处于活动状态。被隔离到其他 Chromium 进程中的跨站
  frame 会被标记为省略，并且无法跨越 guest 安全边界进行控制。
- 暂不提供 Windows ARM64 和 Linux ARM64 包，直到其原生 PTY、SQLite、进程隔离和打包 runtime gate
  能够在匹配的 CI 环境中执行。
- Windows 直接下载目前还没有 Authenticode publisher 证书；Microsoft Store 包由 Microsoft 签名。
  Store 版本可能要在 Microsoft 独立认证完成后才会跟进直接 stable release。
